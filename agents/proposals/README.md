# Improvement and memory proposals

Store proposals here with a stable ID and exact diff; source task/trace/evidence; cause hypothesis and confidence; baseline/candidate evals; affected role/skill/knowledge/memory version; privacy/safety review; independent reviewers; approval state; staged rollout and rollback. Candidate skills and evals belong in an isolated subdirectory such as `<proposal-id>/skills/<name>/SKILL.md`; they are not live skills until independently reviewed, owner-approved, and promoted by a separate authorized task. The project owner has delegated proposal-space writes and local synthetic evaluation; this does not grant write access to live skills, registry, runtime, approved memory/knowledge, permissions, or approval state. Mark pending proposals `PROPOSED`; never present a model-generated review as human approval.
