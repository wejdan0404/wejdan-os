# Contract-first role delivery

1. Read the exact role contract, task packet, required deliverable, tool grants and relevant project source of truth.
2. Restate the concrete objective, inputs, constraints, acceptance criteria, exclusions, owner and stop conditions. Ask for only critical missing inputs; label unresolved ones.
3. Produce the declared role-specific artifact, not generic advice. Use a recognizable structure that mirrors the contract and includes actionable content.
4. Link claims to provided evidence. Mark unknown evidence, tests, costs, approvals and device/environment validation as unknown or not run; never simulate confirmation.
5. Include explicit next steps, owner and decision/approval state when required. A recommendation is not an approval.
6. Before finalizing, map every acceptance criterion to artifact evidence. Reject empty sections, copy-forward drafts that do not resolve review findings, unsupported completion status, and unrelated boilerplate.
7. Return artifact path/hash or stable reference, task/trace/role IDs, reviewer state, evidence limits and remaining open items. Keep synthetic/model review distinct from human review.
