# وظيفة التحسين المستمر لوكلاء Wejdan Life OS

**الحالة:** `IMPLEMENTED_LOCAL_DAILY_REVIEW` — وظيفة تحسين محكومة تحت AI-01؛ نتائج المراجعة بوابات وليست اعتمادًا تلقائيًا.  
**المالك:** AI-01.  
**المراجعة المستقلة:** AI-QA وQA-01؛ وتضاف مراجعة المجال والأمن والخصوصية حسب التغيير.  
**الاعتماد النهائي:** Wejdan أو مالك مفوض صراحة.  
**الصلاحية المفوضة الآن:** إنشاء/تعديل المرشحين في `agents/proposals/` وتشغيل evals محلية اصطناعية فقط.

## المهمة

مراجعة آثار العمل المصرح بها للـ85 دوراً، اكتشاف حالات الفشل المتكررة، تحديد طبقة السبب استناداً إلى الأثر، وإعداد أصغر تغيير قابل للرجوع في السياق أو المعرفة أو skill أو العقد أو المقيّم أو orchestration. مُنحت الوظيفة صلاحية **التحليل والكتابة في مساحة المقترحات فقط**: تستطيع إنشاء مسودة skill جديدة، ومسودة تعديل skill قائمة، وإضافة حالات انحدار اصطناعية، وتشغيل التحقق المحلي المحدد. لا تستطيع الكتابة إلى المسارات الحية أو اعتماد التغييرات أو منح نفسها/غيرها صلاحيات تنفيذ.

هذه الصلاحية مفوضة من مالك المشروع في طلبه بتاريخ 2026-10-19، وتقتصر على الملفات المذكورة أعلاه. إنشاء أو تعديل مسودة داخل `agents/proposals/` لا يعني اعتمادها أو إسنادها في `agents/registry.json` أو تحميلها في runtime.

## المدخلات المسموحة

- العقد الرسمي وسجل الجاهزية الحالي.
- task packet، manifest السياق، نسخة skill/knowledge المستخدمة، وtraces منقحة.
- artifact الفعلي، evaluator/reviewer results، ونسخ regression/eval المعتمدة.
- معلومات التكلفة/الزمن إن توفرت ومن دون توسيع جمع البيانات.
- حالات اصطناعية افتراضياً؛ حالة استخدام تشغيلية فقط بتفويض صريح وتنقيح الهوية والبيانات.

## دورة العمل

1. اكتشاف: rejection، فشل deliverable، تكرار مراجعة دون تغيير، ادعاء غير موثق، فشل استرجاع أو انحراف سلامة/خصوصية.
2. إعادة الإنتاج: ربط role/contract/version/task/trace/evidence/artifact/grader بأصل محفوظ غير معدل.
3. تحديد السبب: تصنيف stage (input/context/memory/retrieval/skill/prompt/tool/model/orchestration/schema/evaluator/review) وإرفاق الثقة والأدلة. `unverified` صالح عند نقص الأدلة.
4. اقتراح: تغيير أولي واحد صغير، فرضية قابلة للتفنيد، مؤشر نجاح ومقاييس محمية، owner/reviewers، تأثير الذاكرة/المعرفة/المهارات، وتراجع. أنشئ مسودة Skill فقط بعد دليل من حالتين مستقلتين أو إجراء إلزامي واحد عالي المخاطر موثق؛ وإلا حسّن التوجيه أو skill موجودة أو eval. اجعل الـskill محددة ومحمولة، ذات trigger ضيق، ومصادر معتمدة، ومدخلات/مخرجات وحدود وفحوص حقن.
5. تقييم: الحالة الفاشلة نفسها، مجموعة الذهب الخاصة بالدور، مدخلات غامضة/ناقصة/متعارضة، multilingual عند الحاجة، adversarial injection/tool misuse، وضوابط الأدوار غير المتأثرة. لا تخفض أي معيار.
6. مراجعة منفصلة: AI-QA للسلوك وصحة التقييم، domain owner للحقيقة التخصصية، QA-01 للبوابة، AI-11/SEC للأمن والخصوصية، PMO-04 للمعرفة، AI-01 للتصميم. مراجعة النموذج ليست اعتماد خبير بشري.
7. مرحلة مقترح: اكتب مسودات التغيير في مجلد معزول مثل `agents/proposals/<proposal-id>/`، واحفظ skill مرشحة تحت `skills/<candidate>/SKILL.md` داخل المجلد. استخدم `agents/proposals/skill-proposal-template/README.md` كقائمة التسليم. أرفق diff، مصدر الدليل، evals، نتيجة التحقق، مالك المراجعة وحالة `PROPOSED`.
8. اعتماد وتطبيق: وظيفة التحسين لا تملك صلاحية نقل skill إلى `agents/skills/` أو تعديل registry/card الحي أو تفعيل runtime. ينفذ ذلك مالك مخوّل بعد مراجعة مستقلة AI-QA وQA-01 ومراجع التخصص والأمن/الخصوصية عند الحاجة، ثم يصرح مالك المشروع بالتطبيق. احتفظ بالنسخة السابقة وhash والتراجع.

## التشغيل اليومي

- يجري AI-01 مراجعة يومية للـ85 دورًا، وسلامة روابط المهارات والمعرفة، وأحدث أدلة القبول ونتائج مجموعة التقييم. وتُعاد المراجعة مباشرة عند تسجيل رفض أو تراجع.
- `ops/local-live/runtime/run-daily-agent-review.mjs` ينشئ تقريرًا ساكنًا من metadata المصرح بها تحت `ops/evidence/daily-agent-review/`. لا يقرأ نصوص مهام تشغيلية أو بيانات شخصية ولا يستدعي نموذجًا.
- تتكون مجموعة الإصدار من 850 حالة اصطناعية (10 لكل دور). تُشغّل باستخدام `ops/local-live/runtime/run-agent-eval-suite.mjs --execute` عند تقييم مرشح تغيير، لا ضمن المراجعة اليومية كي لا تشغل الجهاز باستدلالات متكررة. نتائج هذه المجموعة ومراجعتها المستقلة شرط منفصل عن التقرير الساكن.
- يشخّص AI-01 النتائج ويجهز مقترحات معزولة فقط. كل ترقية لنسخة معتمدة تتطلب مراجعة مستقلة وموافقة مالك صريحة؛ لا يمنح نجاح التقرير صلاحية نشر.

## تقارير القياس

سجّل numerator/denominator، الفترة، نوع الحالة (synthetic أو تشغيلية منقحة)، الثقة، القيم غير المعروفة كـ`null`، ونتائج منفصلة لكل دور. تشمل المؤشرات إكمال deliverable، نجاح المراجعة، معالجة revision بتغيير فعلي، grounding، مخالفة الأدوات/السياسة، عزل الذاكرة، زمن/تكلفة التشغيل، وعبء المراجعة. لا تجمع plumbing pass، تقييم النموذج، حكم domain expert، واعتماد الإنسان في درجة واحدة.

## منع التحسين الذاتي غير الآمن

- صلاحية كتابة محدودة إلى `agents/proposals/` لإنشاء نسخ مرشحة من skills/evals/تقارير؛ لا كتابة خارج مساحة المقترحات، ولا نشر أو اعتماد أو تعديل صلاحيات/ميزانيات.
- إنشاء Skill لا يضيفها لقائمة skills النشطة. لا تعدل `agents/skills/` أو بطاقات الأدوار أو `agents/registry.json` من وظيفة التحسين.
- لا ترقية تلقائية لمخرجات المهمة إلى ذاكرة role أو project.
- PMO-04 يراجع معرفة المشروع؛ AI-09 يراجع سياسة الذاكرة؛ AI-12 يدير حزم القياس؛ AI-QA يراجع باستقلال.
- كل كتابة ذاكرة مقترحة تحمل role/task/trace provenance وevidence refs والثقة والحساسية والتاريخ والحالة. تظل `PROPOSED` حتى موافقة المالك.
- تصعيد فوري عند خرق خصوصية/عزل، prompt injection، إساءة أداة، أثر خارجي أو حاجة لمصدر/صلاحية غير ممنوحة.

## حدود الحالة الحالية

لا يوجد دور رسمي `AI-14` في العقد المرجعي؛ لذلك الوظيفة تحت AI-01 وليست عاملاً منفصلاً. الكتابة إلى proposal space مفوضة فقط، أما الإسناد/التفعيل/الاعتماد فليس مفوضاً. يوجد مسار محلي في `rolePrompt()` للذاكرة والسياق والمهارات. يلزم تحقق مستقل من مصادقة المستدعي، عزل الأدوار، اكتمال السياق بعد truncation، الاحتفاظ/الحذف والنسخة الفعلية قبل اعتباره جاهزاً إنتاجياً. توجد 9 حالات انحدار محفوظة؛ لم تثبت كلها إصلاحاً. لا توجد موافقة خبير بشري في مصفوفة 2026-10-19.
