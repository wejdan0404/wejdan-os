## 1. Ground rules

1. The product is built and tested. **Do not rebuild, re-skin, re-architect or "clean up" finished areas.** The only open work is in `18_REMAINING_BACKLOG.md`.
2. Read `00_HANDOFF_INDEX.md` §3 (hard rules) and `15_DECISION_LOG.md` before the first edit. Owner-approved decisions override any generic instruction you were given earlier.
3. Evidence over memory: when you state a result, say how you got it (command, file, line). Use `UNKNOWN`/`NOT VERIFIED` when you have no evidence.
4. Test data you create is named `test`.
5. Never place personal data in the repo: no routine/product contents, personal action library, health items, recovery codes, tokens, e-mail, anything from a private scratchpad. Run `npm run privacy:scan` before every push.

## 3. First task (do exactly this first)

**Goal:** establish a trustworthy baseline of the handoff snapshot; make no product changes yet.

1. `git status` and `git log --oneline -5`: confirm you are on the intended commit (the snapshot or a descendant).
2. `npm ci`, `npx tsc --noEmit -p tsconfig.app.json`, `npm test`, `npm run build`, `npm run privacy:scan`. Record counts and any failure. If the routine-player test fails, rerun that file alone and note the result (LOS-003).
3. Run the e2e scripts that pass today (`bidiGlyphOrder`, `joyOnboarding`, `studioOnboarding`) in light and dark; the other nine need the onboarding helper from LOS-044 first, so do that before relying on `lockKill`. Save screenshots outside the repo.
4. Open the app at 390×844 (ar-SA locale, Asia/Riyadh) and walk the happy path from `LOS-002`, including: enable the lock, kill the tab, reopen, unlock.
5. Write a short report (Arabic summary for the owner on top) listing: what passed, what failed with reproduction steps, what you could not verify. Do not fix anything in this step unless a failure blocks setup.
6. Then continue with `19_NEXT_DEVELOPMENT_PLAN.md` Phase 1.

## 4. How to validate your own changes

| Change type | Minimum validation |
|---|---|
| Domain/engine/store | The matching `tests/domain/*.test.ts`, then full `npm test`; add a test for new behaviour |
| UI screen | Matching `tests/ui/**` test + a Chromium run at 390×844 in light and dark; check RTL, no horizontal overflow, targets ≥ 44 px, toast not covering controls |
| Storage / lock / backup | `tests/domain/vault*.test.ts`, `repository.test.ts`, `store.test.ts`, `tests/e2e/lockProfiles.e2e.mjs`; verify export → wipe → restore round trip |
| Styling/tokens | Both themes; contrast numbers (LOS-007); never alter the four identity colours |
| PWA | `npm run build`; offline reload test (service worker active, reload with the server stopped); update-prompt behaviour |
| Copy | Saudi dialect, no guilt; plural/bidi rules (see `src/ui/lib/plural.ts`, `Bidi.tsx`) |

Done means: `npx tsc --noEmit -p tsconfig.app.json` clean, `npm test` green (allowing the documented flake, re-run alone), `npm run build` succeeds, `npm run privacy:scan` passes, and the relevant manual/e2e check passed with evidence you can quote. The full Definition of Done is `AGENTS.md` §11.

## 5. Needs the owner's explicit approval first

Ask in Arabic, in one short message with the exact action; wait for a clear yes in that conversation. A past approval does not carry over.

| Action | Why it needs approval |
|---|---|
| **Pushing to `main`** (or any shared branch), or **pushing any git history** | Public repo; the owner's rule is "no push/commit/publish without an explicit request". Committing to a local/feature branch is fine when asked; the public push is the integrator's single clean snapshot (D-64) |
| **Publishing to `gh-pages`** | Replaces the live app on her phone; each publish is a separate approval (LOS-001) |
| **Any history rewrite** (force-push, filter-branch, BFG, rebase of published history) or making the repo private/changing its settings | Destroys hashes and links; she said to leave history as it is (D-52) |
| **Adding any server, remote call, analytics, sync, push service or third-party script/font CDN** | Violates local-only (D-32); `fetch`/XHR/WebSocket currently have zero uses in `src/` |
| **Changing identity colours** or adding an accent/gradient colour | Identity is fixed (D-01) |
| **Enabling any health / medical / women's-health item or module**, or adding such content | Privacy (D-54); it is off by default and absent from the public build |
| **Adding any real personal data** (routine, products, library) to the repo, tests, logs or docs | Public repo (D-53) |
| **Changing product behaviour decisions** (suggestion mode, five tabs, payday day 1, momentum/sparks, language, fonts) | Owner-approved (D-03…D-12) |
| Removing the Flutter takeover shims (LOS-021) | Could blank an old cached install |
| Adding `.github/workflows` | Publishes CI config in a public repo; keep test-only if approved |
| Anything on real devices / Xcode | Permanently deferred by the owner (D-50): do not request |

## 6. Publishing checklist (only after approval for that publish)

### 6.1 Source snapshot to GitHub (integrator; PLANNED branch `react-app`)

1. Working tree clean, on the approved commit; `npx tsc --noEmit -p tsconfig.app.json`, `npm test`, `npm run build` pass.
2. `npm run privacy:scan` passes **on this exact tree**; then run the extra grep from `22_COLD_START_AUDIT.md` §6 over `docs/`, `README.md`, `AGENTS.md`, `CODEX_START_HERE.md`.
3. Create **one** orphan snapshot commit of the tree (not the local history; local history is unpublished — `16` §0), push it to a **new** branch `react-app`; never to `main`, never forced, never a history upload.
4. Fill the real branch name and commit SHA into `docs/handoff/HANDOFF_MANIFEST.json` (`repository.commitSha`, currently `PENDING_PUSH`) and the status in `21_FINAL_HANDOFF_REPORT.md` §3, in a follow-up commit.

### 6.2 Live site (`gh-pages`)

1. Working tree clean, on the approved commit; gate commands above pass.
2. `npm run privacy:scan`, plus grep decoded `dist` for the removed module's keywords, owner name/goals, e-mail patterns and tokens; expect 0.
3. Check `dist` contains `sw.js`, `manifest.webmanifest`, the four `flutter*`/`main.dart.js` shims and (after copying) `.nojekyll`.
4. Update the `gh-pages` branch with a normal commit (no force); the commit message should name the source commit; keep the Co-Authored-By trailers required by the environment.
5. Wait for Pages, then verify: live HTML names the new `assets/index-*.js`; manifest scope `/wejdan-os/`; offline reload works; console 0 errors.
6. Rollback: republish the previous `gh-pages` commit. Per the integrator the live site is release 3 (the wave, built from `d982b01`; its `gh-pages` SHA is `d2db69a`) and release 2 was `f7e1f75` (build of `main` @ `ed0df23`, the rollback target); the one before it was the first React publish (`169ca40`, 2026-10-24 08:15 UTC, built from `0fa7aa6`) in the integrator's local clone, whose availability is UNKNOWN.
